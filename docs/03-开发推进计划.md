# 开发推进计划

> 依据：《01-技术方案》十二节里程碑总表。本文档展开每个里程碑的**内部执行顺序**与排序理由，是日常开发的操作手册。gate 未过不进下一里程碑。

## 排序五原则

1. **纵向切片**——每个里程碑交付可运行可验证的业务闭环，拒绝横向分层（先全部后端再全部前端=集成风险全部后置到末期）
2. **横切面最先**——schema/认证/i18n/双壳/时区/审计/日志在 M1 一次落齐，此后业务模块只做加法（横切面事后改造成本指数级，且是漏审重灾区）
3. **风险前置**——全项目最高风险（管理号并发）用 TDD 在 M2 最先验证、iOS 真机 M1 尾即首验、Windows Docker M0 首查——风险暴露越早修复成本越低
4. **外部依赖早触发不阻塞**——必问 4 项（A1/A3/A6+A20）M0 后立即发确认单，默认值均已落地，甲方未答不等待（A4 有 M4 死线+合成 fixture 兜底）
5. **每会话必推送**——git 纪律贯穿全程，任何时点仓库=可部署状态

## P0 文档落库（M0 第一步之前）

`git init` + .gitignore + 首推 GitHub（验证远端可达+提交身份）→ docs/01-技术方案、02-参考项目、03-开发推进计划（本文档）、04-决策记录 入库推送。

为什么文档先于代码：四份文档是后续每次提交的对照基准与验收口径，代码偏离文档=缺陷，文档不存在=无对照。

## M0 工程底座

1. git init+首推（一切工作先版本化，最先验证 SSH/仓库/身份链路通）
2. 四份文档入库推送
3. **开发环境预检**：Docker Desktop/WSL2 可用性+JDK21/Node 版本（Testcontainers 与本地 compose 的硬前提；预检失败则修环境优先于一切编码）
4. `server/` Spring Boot 脚手架（依赖当日 `mvn versions` 复核）
5. `web/` Vite 脚手架（`npm view` 复核）
6. Flyway V1__init.sql（17 表+最小 GRANT+verify-grants.sh）——schema 先于一切业务代码，实体/接口全部以它为契约
7. 本地 compose 全栈 healthcheck 绿（app↔mysql 连通验证）
8. CI 流水线+Dependabot
9. 提交审计复查（`git log --format='%an %ae' | sort -u` 仅统一身份 + 关键词扫描零命中）

**出口 gate G0 = CI 绿 + 本地栈起**

## M1 认证与框架（横切面一次落齐）

顺序：Spring Security 配置（Session/RBAC/锁定防爆破）→ 登录/登出/me/改密 → 账号管理 → **审计切面+operation_log（与业务同期落地，绝不后补）** → **可观测性地基（结构化日志/traceId/errorId 闭环/client-errors/sys_alert——与审计同期）** → i18n 三语框架（ja 默认+错误码 key 化）→ 双 shell 布局+UA 路由+手动切换 → JST 时区基建（Clock bean/DateUtil 唯一出口/eslint 拦截裸 `new Date`）→ E2E 冒烟（登录/切语言/三角色权限矩阵首版）→ **iOS 真机首验（登录页+PWA 安装引导）——R1 风险最早暴露点**。

为什么 i18n/双壳/审计在 M1：后续每个页面的每条文案、每个端点的每条审计都依赖它们就位，后补=全量返工。

**出口 gate G1 = 三角色登录+审计+日志闭环**

## M2 管理号引擎+录入（域核心，严格依赖链，TDD 起点）

1. 字典后台（venue / yearcode 种子 2016=A / priceband）——引擎的前置校验依赖字典，先字典后引擎
2. **ItemCodeGenerator + ItemCodeTxService：TDD 先测后码**（单测：组号/进位/补录/A0 快照→Testcontainers：并发 16×50+故障注入矩阵）——全项目最高风险点最早验证，若设计有缺陷此时暴露成本最低
3. 预览接口+clientReqId 读回
4. 连续录入页（沿用逻辑/两级预览/草稿 Dexie）
5. 图片管线（压缩/队列/幂等 200）
6. 作废重录+re_entry_of 互链
7. QR 生成+标签打印页（人读码）
8. 到货核对页+本日录入会话页+首启 checklist
9. E2E 录 10 件闭环

**甲方触发：M2 开始前发确认单（必问 4 项+A0/A20 书面告知）；A1 未答按默认（含价格码）开发，答复后 yml 一键切换。**

**出口 gate G2 = 最早可向甲方演示的业务闭环（录出第一件+打出第一张标签）**

## M3 仓库操作

1. InventoryStateMachine 五元组边表（TDD 全合法边+全非法边枚举）——所有动作端点=边表的展开，先表后端点防口径分叉
2. ledger 双向入账+对账不变量 v1——不变量先于端点：端点即不变量的实现，先写不变量测试=端点的验收标准已就绪
3. SseHub+useSse 管道——先管道后载荷，动作端点落地即接推送
4. 扫码页+按状态动态渲染动作菜单
5. 五类出库/调拨/退货双向端点
6. 盘点全流程（发起/扫码/close/差异/确认+冻结品拦截）
7. 每日自检 job v1

**出口 gate G3 = 全流转+实时同步+盘点闭环**

## M4 对账与数据（不被 A4 阻塞的工程安排）

1. 编码检测链+清洗规则（**合成 MS932/UTF-8 fixture 先行——不依赖真实样张即可开发与测试**）
2. 匹配/合并（单调状态机+recency+确定性场景矩阵）
3. 异步批次管线+sha 幂等+僵尸自愈
4. 对账三活视图+出荷待ち清单
5. Excel 模板/双模式导入/流式导出

**A4 死线=列映射校准前；样张晚到只改 application.yml 重启即适配——架构已为晚到设计，这正是 M4 不被外部依赖卡死的原因。**

**出口 gate G4 = CSV/Excel 全通**

## M5 报表与治理

kw 全局搜索（查询形态按技术方案第六节规格化实现）→ stats 大盘/两仓统计 → 滞销黄红预警 → 回收站恢复 → 流水浏览/日志查询 → system 页+诊断导出。

为什么搜索放 M4 后：列表筛选字段含雅虎同步状态（M4 回写），一次实现全量字段避免二次改造。

**出口 gate G5 = 搜索/报表/治理齐**

## M6 移动端打磨

PWA 完善（SW 更新链路/manifest/apple-touch-icon 全套）→ 弱网补传全矩阵（Background Sync 注册+页面存活循环+visibilitychange）→ 扫码离线小队列（Dexie scan_actions）→ **`docs/qa/device-matrix.md` 工件+真机矩阵执行（100% 完成=M6 出口硬 gate）** → 三语母语级校对。

为什么打磨最后做：打磨对象是已定型的流程，提前打磨=流程变更后重打磨的浪费。

**出口 gate G6 = 真机矩阵 100%**

## M7 测试上线与交付

服务器勘察（**ICP 备案首查**）→ 测试环境部署+deploy.yml CI/CD 打通 → 备份 cron+restore.sh --verify 演练 → 5 万造数压测（按测试策略分布规格）→ 生产部署包干净主机演练+四项安全自检 → 14 条验收逐条+验收报告 → 生产 URL 纳入拨测+文档定稿。

**出口 gate G7 = 交付**

## 并行机会

- M4/M5 互不依赖可并行
- runbook/部署文档在 M5/M6 期间穿插起草
- 真机测试与桌面开发穿插

## 贯穿循环（每个里程碑内部节奏）

TDD（核心域先测后码）→ 实现 → code-review → 安全面 security-review → 回归用例入 @Tag("regression") 套件 → 自行决策点即时入 docs/04-决策记录.md → compose 部署验证+E2E 子集绿 → commit+push（fetch+ff-only 先行）。

**上一里程碑 gate 未过不进下一里程碑。**
