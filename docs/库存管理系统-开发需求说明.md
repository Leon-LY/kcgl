# 二手货品库存管理系统 · 开发需求说明

> 本文档面向开发，完整描述系统"要做什么"，不含技术选型与实现方案。开发方可自行决定技术栈、数据库、部署方式。

## 一、系统概述

**业务**：业务员在日本各拍卖现场落札进货二手货品，运回名古屋、福岡两个仓库，再上架雅虎店铺转售赚差价。

**使用方式**：手机、电脑通过浏览器访问，无需安装独立 App；手机端支持添加到主屏、像 App 一样使用。

**数据同步**：手机、电脑看到的是同一份数据，多人同时操作实时一致。

**账号规模**：10 个以内。

**编号原则**：管理号码是系统内部唯一编号，用于扫码定位商品和雅虎匹配；二维码只是管理号的图形形式。

## 二、用户角色与权限

| 角色 | 权限 |
|------|------|
| 管理员 | 全部权限：录入、出库、修改、删除（进回收站可恢复）、账号管理、价格档位表维护、日志查看、Excel 导入导出 |
| 可编辑 | 录入、出库、修改、Excel 导入导出；**不能删除商品、不能改价格档位表** |
| 仅查看 | 只读，只能看、搜索、导出，不能做任何改动 |

> 密码登录，连续输错多次自动锁定一段时间。

## 三、商品数据模型

### 3.1 录入字段（手机端填）

| 字段 | 说明 | 必填 |
|------|------|------|
| 管理号码 | 系统自动生成，唯一（规则见第四章） | 自动 |
| 拍卖场名称 | 进货的拍卖场 | ✅ |
| 落札日期 | 竞价中标日期 | ✅ |
| 拍摄日期 | 每件商品拍照日期；没拍的显示「未拍摄」 | 自动/选填 |
| 进货单价 | 落札价，货币日元；生成管理号后锁定 | ✅ |
| 手续费 / 运费 / 消费税 | 成本分项，可空、事后补录，计入总成本 | 选填 |
| 入库日期 | 货到仓的日期，滞销预警的起算点 | 选填 |
| 仓库 | 名古屋 / 福岡 二选一 | ✅ |
| 货架号 | 货架位置 | 选填 |
| 备注 | 自由文本 | 选填 |
| 同款组号 | 2–3 件同款时归为一组（每件仍独立编号） | 选填 |
| 图片 | 一件多张，拍照/相册上传，自动压缩 | 选填 |

### 3.2 雅虎对接字段（从 CSV 导入）

| 字段 | 说明 |
|------|------|
| 雅虎商品 ID | 雅虎店铺的商品 ID |
| 挂牌价 | 雅虎当前在售价 |
| 成交价 | 实际售出价格 |
| 出品次数 | 累计出品次数 |
| 取消记录 | 取消次数 / 是否被取消过 |

### 3.3 系统自动字段

| 字段 | 说明 |
|------|------|
| 二维码 | 绑定管理号 |
| 录入时间 / 操作人 | 自动记录 |
| 库存状态 | 在途 / 在库 / 已出库 |
| 销售状态 | 未上架 / 在售 / 成交 / 取消 |
| 总成本 | 进货单价 + 手续费 + 运费 + 消费税 |
| 利润 | 成交价 − 总成本 |

## 四、管理号生成规则

### 4.1 格式

```
会场代码(2位) + 年份代号(1位) + 月(1-2位) + 流水号 + 价格代码(1位)
例：HTK9-A1X
```

| 段 | 含义 |
|----|------|
| HT | 会场代码（拍卖场） |
| K | 年份代号（后台「年份↔代号」对照表，如 2026=K、2027=L；买家看不出是年份） |
| 9 | 月份 |
| A1 | 流水号：A1~A99 排满自动切到 B1~B99，按「会场 + 年份代号 + 月」连续递增 |
| X | 价格代码（进货价档位字母） |

- 年份代号：后台维护「年份 ↔ 代号」对照表，每年分配一个代号；编号中不出现具体年份数字
- 流水号按「会场 + 年份代号 + 月」连续递增，跨年代号不同、流水号重新排起，不重号
- 管理号生成后锁定：改进货价、改拍卖场都不改号；录错则作废重录（原号标记作废、不复用）
- 月份、价格档位保留在编号中（供内部识别），年份以代号隐藏

### 4.2 价格档位表

- 后台维护一张「进货价区间 ↔ 字母代号」对照表，管理员可增删改
- 区间采用左闭右开（如 [1000, 2000) 表示 1000~1999）
- 用途：录入进货价时，系统自动判断落在哪个档位，把档位信息记在商品字段里（供内部看，不进编号）
- 改档位表只影响之后新录入的商品，历史商品不回溯
- 具体档位划分（分几档、每档边界）待甲方提供

## 五、二维码

- 每件商品生成一个独立二维码，内容为管理号
- 支持批量打印（按录入顺序排版到 A4 不干胶标签纸）
- 支持对任意商品重新打印（管理号不变）
- 标签尺寸、打印设备待甲方确认

## 六、状态与流转

### 6.1 库存状态

`在途 → 在库 → 已出库`

- 录入后默认「在途」（货还在拍卖场运回的路上）
- 货到仓扫码确认 → 「在库」
- 出库 → 「已出库」

### 6.2 销售状态

`未上架 → 在售 → 成交`（另有「取消」）

- 未上架：在库但还没挂到雅虎
- 在售：已上架雅虎、正在卖
- 成交：雅虎已售出
- 取消：上架被取消 / 流拍下架 / 退货

## 七、核心流程

### 7.1 商品录入（手机端）

1. 一件一件录入，单次可连续录 10–100 件
2. 连续录入：保存一件自动清空进入下一件；拍卖场、仓库、日期、单价沿用上一次，落札日期默认当天
3. 录入进货价时，实时预览价格档位字母和完整管理号
4. 支持拍照 / 相册选图，一件多张，上传即压缩
5. 保存后自动生成管理号 + 二维码

### 7.2 到仓入库

- 扫码 → 调出商品 → 确认入库 → 库存状态「在途 → 在库」→ 登记仓库、货架号、入库日期

### 7.3 出库 / 库存变动（分类型）

每次变动必须选类型，扫码 → 调出 → 确认 → 完成：

| 类型 | 库存变化 | 说明 |
|------|---------|------|
| 卖出 | 在库 → 已出库 | 扣库存，关联雅虎成交 |
| 报废 | 在库 → 已出库 | 扣库存，记原因，不关联售价 |
| 调拨 | 仓库变更 | 名古屋↔福岡，总库存不变 |
| 退货 | 库存加回或扣减 | 顾客退回则加回；退回拍卖场则扣减（录入时选方向） |

### 7.4 扫码盘点

- 按仓库发起盘点，手机逐个扫码核对
- 生成盘盈盘亏差异表（实扫数 vs 系统数）
- 差异经人工确认后才调整库存（不能自动直接改）

### 7.5 雅虎同步（CSV 半自动）

1. 甲方在雅虎后台导出商品 CSV，上传到本系统
2. 系统识别 CSV 的日文编码、清洗格式（全角/半角、货币符号）
3. 以管理号为键匹配到本系统的商品
4. 多次出品的数据合并；重复导入同一份 CSV 不重复计数
5. 展示挂牌价、成交价、出品次数、取消记录；已下架商品也能对账
6. 雅虎 CSV 没导入时，本地录入、扫码、出库照常用，雅虎字段显示「最后同步时间」

## 八、双仓库管理

- 区分名古屋倉庫、福岡倉庫两个仓库
- 每件商品记录所在仓库、货架号
- 各仓库存独立统计、可切换查看
- 支持两仓调拨（见 7.3）

## 九、数据与报表

### 9.1 全局搜索

- 顶部搜索框，按管理号 / 备注 / 拍卖场 / 日期等关键字快速定位商品

### 9.2 总成本与利润

- 总成本 = 进货单价 + 手续费 + 运费 + 消费税
- 利润 = 成交价 − 总成本
- 售出后自动显示

### 9.3 滞销黄 / 红预警

- 入库超 N 天未售出 → 标黄提醒
- 入库超 M 天未售出 → 标红提醒
- N、M 可在后台设置

### 9.4 Excel 导入导出

- 支持按模板批量导入库存数据
- 支持全部库存数据导出 Excel

## 十、操作日志与删除

- 所有库存变动（录入、出库、修改、删除、导入导出）自动记录：时间、操作人、动作、商品
- 删除是"放进回收站"（软删除），可恢复；删除后管理号不复用
- 日志不可删改，管理员可查看

## 十一、多语言

- 界面支持中文 / 日文 / English 三语切换
- 菜单、按钮、字段名、提示信息随语言切换
- 各用户可自行选择界面语言
- 业务数据（商品名称、备注）按录入时语言原样保存，不做翻译

## 十二、移动端行为

- 手机浏览器访问，可添加到主屏、像 App 一样用
- 手机浏览器可直接调摄像头拍照、扫码（需安全网络环境）
- 弱网场景：图片排队上传、失败自动重试；文字先保存、图片后补传
- 图片补传：安卓可后台自动上传；苹果在打开系统时自动补传

## 十三、异常与边界

- **录错价格/拍卖场**：管理号已锁定，改字段不改号；错价走"作废重录"（原号作废、不复用、留痕）
- **重复录入**：系统不自动判断同一件实物录了两次；靠现场"录一件贴一件"流程兜底
- **扫错码**：出库前有确认步骤，确认页展示照片、管理号、仓库、备注，供核对
- **并发录入**：多业务员同时录同一会场，流水号不能重
- **超量**：商品总量按最多 5 万件、日常 1000 件设计，性能须流畅

## 十四、验收标准

1. 手机、电脑浏览器均可登录，三级权限正常
2. 手机拍照/相册多图上传正常，图片自动压缩，弱网下排队上传
3. 管理号按规则自动生成、唯一、锁定；价格档位表可后台维护；录入时实时预览
4. 每件商品生成独立二维码，可打印、可扫码定位、可重新打印
5. 库存变动分类型（入库/卖出/报废/调拨/退货），库存正确流转
6. 名古屋/福岡两仓独立统计正确，调拨正常
7. 雅虎 CSV 可导入、按管理号匹配、重复导入不重复计数，售价/出品次数/取消记录正确展示
8. Excel 导入导出正常
9. 操作日志完整可查，软删除可恢复
10. 界面中日英三语切换正常
11. 库存状态、销售状态正确流转
12. 全局搜索、扫码盘点、总成本利润、黄红预警正确
13. 拍摄日期显示正确（未拍显示「未拍摄」）
14. 存量数据（如有）导入无误

## 附：待甲方最终确认的事项

1. 管理号格式：采用 `会场代码 + 年份代号 + 月 + 流水号 + 价格代码`（例 HTK9-A1X），年份以代号隐藏、月份价格保留可读；需甲方确认年份代号的起始字母
2. 价格档位表的具体分档（几档、每档边界）
3. 雅虎真实 CSV 样张（用于核对编码格式和「商品コード」字段到底填什么）
4. 二维码标签尺寸、打印设备
5. 商品字段清单：甲方早期列过「商品名称、商品分类、作者·窑口、尺寸·重量、品照片/底款照片（区分）、出品日期、出库日期·销售渠道」等字段，后续需求简化时未明确是否保留，需甲方确认最终字段清单
