# 二手货品库存管理系统 · 技术方案

> 版本：1.0｜日期：2026-09-27｜作者：Leon-LY｜状态：已定稿
> 需求依据：《库存管理系统-开发需求说明》
> 本方案对照需求 14 条验收标准逐条落点，经需求忠实度、后端架构、安全部署、前端移动端、测试策略、可观测性六个维度的多轮设计评审迭代定稿。
> 机制唯一定义节纪律：幂等=7.0／时区=7.8／备份=9.2／管理号锁定=7.1，其余位置仅引用——规格内部矛盾会 1:1 变成实现缺陷。

---

## 一、背景与目标

**业务**：业务员在日本拍卖现场落札二手货品 → 运回名古屋/福岡两仓 → 上架雅虎店铺转售赚差价。本系统管理从「落札录入」到「售出结算」的全生命周期。

**目标**：交付手机优先、电脑可用的 B/S 库存管理系统，满足需求 14 条验收：手机连续录入+拍照、管理号自动生成（并发防重）、二维码打印/扫码定位、分类型库存流转、双仓调拨、盘点差异人工确认、雅虎 CSV 半自动对账、Excel 导入导出、成本利润与滞销预警、中日英三语、软删除回收站、不可删改日志、PWA 弱网图片补传。

**关键约束**：
- ≤10 用户、商品 5 万件上限、日常录入 1000 件/天，性能须流畅
- 系统在日本使用、用户以日本人为主（默认语言/时区/IME/字体/真机适配见 7.8）
- 手机浏览器直接使用（PWA 加主屏），摄像头拍照/扫码强制 HTTPS
- 测试部署于 49.232.49.175（上有其他项目，必须零影响隔离）；正式生产由甲方自行部署到日本服务器——交付可自助部署的完整部署包
- 代码托管 git@github.com:Leon-LY/kcgl.git

## 二、技术决策总表

| 决策点 | 结论 |
|--------|------|
| 后端 | Java 21 + Spring Boot ≥3.5 + MyBatis-Plus + MySQL 8.4 LTS（utf8mb4_0900_ai_ci） |
| 前端 | Vue 3 + TS + Vite；Vant 4 移动端 / Element Plus 桌面端（单 SPA 双 shell） |

**关键页面规格**：
- **扫码页**：后置摄像头、torch、800ms 冷却+同码去重（蜂鸣+振动）；扫得管理号→调商品→确认卡（缩略图/号/仓/备注）→执行动作（菜单按五元组边表以当前状态动态渲染，只显示当前态合法动作）；手动输入框兜底
- **连续录入页（验收核心）**：保存成功→大字号最终管理号+本地二维码+计数+「作废重录上一件」，明示「录一件抄一件（油性笔）+回社贴一件（标签）」流程约定；沿用上一件：拍卖场/仓库/落札日期/单价；首件或无历史时落札日期默认当天 JST；入库日期选填（预填则到仓扫码不覆盖）；单价防抖 300ms→本地档位字母+流水号两级预览（预览≠保留，文案明示「以保存为准」）；草稿+照片先落 IndexedDB，iOS 相机重启可恢复；保存拿到 itemId 后照片后台补传（角标 N）；保存失败弹层提供「重试（同请求）」复用同 clientReqId；沿用值≠今天时字段旁显示「（前日）」角标
- **到货核对页**：按预计仓库筛选在途件，卡片式缩略图+管理号+会场，逐件点选确认入库（同一 ARRIVAL 事务），页头「本日已到 N／在途余 M」——承载「货直送仓库、标签还在办公室」路径
- **本日录入会话页**：created_by+当天过滤，大字号码+缩略图列表，现场誊写与收工对数
- **标签打印页（桌面）**：筛选（创建日期+会场）→按录入顺序 A4 排版；`@page A4` + `--label-w/--label-h` CSS 变量（sys_setting 驱动，预置 38×21 不干胶 5×13/页、50×30、70×25）；50×30/70×25 提供「带缩略图」排版开关；`break-inside:avoid`；二维码内容恒为管理号，重打恒有效；**标签必含人眼可读管理号文字（会场/日期段分行）**——QR 破损后手输兜底的前提；单件重印=详情页同组件 n=1

**UI 设计规范（强制）**：
- **无模板感**：禁用千篇一律的渐变主色+重阴影卡片堆砌+emoji 当功能图标+无意义动画；视觉基准=日本成熟業務 SaaS（Zaico/freee 系）：克制的单主色+中性灰阶、信息密度合理、栅格对齐、真实业务系统质感
- **美观**：设计 token 统一（间距 4/8 栅格、圆角/阴影/字号各 2-3 档、每 shell 一份 CSS variables）；日文排版细节（行高 1.6+、字重层次、禁半角标点混排）；移动端触控目标 ≥44px；空态/加载/错误三态都有设计；图表配色与主色系一致
- **交互便捷**：高频路径点击数最少化（连续录入存一件 ≤3 击、扫码确认 2 击）；表单错误就地即时提示；危险操作二次确认但不过度打断流水作业；桌面端键盘友好（回车提交/Esc 关闭/⌘K 聚焦搜索）
- **落地机制**：共享组件先行再拼页面；三语布局以日文最长文案为基准设计不破版；每页完成后对照检查清单自查+截图留档

## 五、数据模型（17 张表，Flyway V1__init.sql）

**通用约定**：金额 INT UNSIGNED（日元，应用层单值上限 99,999,999 円、聚合查询一律 Java long）；profit 为 BIGINT；时间 DATETIME(3)（全库 Asia/Tokyo，实体一律 LocalDateTime；**禁 TIMESTAMP 列与 Instant/OffsetDateTime 实体**——引入即激活换算路径破坏恒等链路，code-review 检查项）；`deleted`（回收站）与 `voided`（作废）分离且号均不复用；流水/日志表只增不改不删；物理外键全库不用（逻辑外键+索引），便于备份迁移；窄域 CHECK 约束：buy_month 1-12 / seq_no 1-99 / cur_seq 0-99 / warehouse IN(1,2) / stock_status 0-2 / sale_status 0-3；JDBC `rewriteBatchedStatements=true`（批量提速 10-50 倍）+ Excel/CSV 导出流式 fetch（防 5 万行实体进 640M 堆）；排序规则全库统一 utf8mb4_0900_ai_ci 不混用（uk_item_code CI 判重=全半角/大小写容错是净收益；不引入 ja_as_cs 按列混排——跨表 Illegal mix of collations 风险大于收益）。

### 5.1 商品主表 item（核心）

```sql
CREATE TABLE item (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  item_code      VARCHAR(16)  NOT NULL COMMENT '管理号 如HTK9-A1X',
  venue_id       BIGINT UNSIGNED NOT NULL, venue_code CHAR(2) NOT NULL COMMENT '会场码快照',
  year SMALLINT NOT NULL, year_code CHAR(1) NOT NULL COMMENT '年代号快照',
  buy_month TINYINT NOT NULL COMMENT '1-12不补零', seq_prefix VARCHAR(3) NOT NULL,
  seq_no SMALLINT NOT NULL,
  buy_date       DATE NOT NULL, photo_date DATE NULL COMMENT 'NULL=未拍摄',
  purchase_price INT UNSIGNED NOT NULL COMMENT '进货单价(锁定档位依据,应用层上限99999999)',
  fee INT UNSIGNED NULL, shipping_fee INT UNSIGNED NULL, tax INT UNSIGNED NULL,
  sold_price     INT UNSIGNED NULL COMMENT '成交价(CSV>手填,见7.2);置于生成列之前防脆弱列序依赖',
  total_cost     INT UNSIGNED AS (purchase_price+IFNULL(fee,0)+IFNULL(shipping_fee,0)+IFNULL(tax,0)) STORED,
  profit         BIGINT AS (CAST(sold_price AS SIGNED)-CAST(total_cost AS SIGNED)) STORED COMMENT '未售=NULL自然传播',
  price_band_code CHAR(1) NOT NULL COMMENT '录入时档位快照,不随档位表回溯',
  warehouse      TINYINT NOT NULL COMMENT '1名古屋 2福岡', shelf_no VARCHAR(32) NULL,
  warehouse_in_date DATE NULL COMMENT '入库日期,滞销起算',
  group_no VARCHAR(32) NULL, remark VARCHAR(500) NULL,
  re_entry_of BIGINT UNSIGNED NULL COMMENT '作废重录前后件互链',
  ext_json JSON NULL COMMENT '甲方扩展字段预留(名称/分类/作者窑口/尺寸重量/销售渠道)',
  stock_status   TINYINT NOT NULL DEFAULT 0 COMMENT '0在途1在库2已出库',
  sale_status    TINYINT NOT NULL DEFAULT 0 COMMENT '0未上架1在售2成交3取消',
  yahoo_item_id  VARCHAR(32) NULL, list_price INT UNSIGNED NULL,
  yahoo_listing_count INT NOT NULL DEFAULT 0, yahoo_cancel_count INT NOT NULL DEFAULT 0,
  yahoo_last_synced_at DATETIME(3) NULL,
  voided TINYINT NOT NULL DEFAULT 0, void_reason VARCHAR(255) NULL,
  deleted TINYINT NOT NULL DEFAULT 0, deleted_at DATETIME(3) NULL, deleted_by BIGINT UNSIGNED NULL,
  created_by BIGINT UNSIGNED NOT NULL, created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_by BIGINT UNSIGNED NULL, updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  version INT NOT NULL DEFAULT 0 COMMENT '乐观锁',
  UNIQUE KEY uk_item_code (item_code),
  KEY idx_wh_stock (warehouse, stock_status, deleted), KEY idx_sale (sale_status, deleted),
  KEY idx_buy_date (buy_date), KEY idx_in_date (warehouse_in_date),
  KEY idx_group (group_no), KEY idx_yahoo_id (yahoo_item_id), KEY idx_creator (created_by, created_at)
) ENGINE=InnoDB COMMENT='商品主表';
```

### 5.2 管理号计数器 seq_item_code（并发核心）

```sql
CREATE TABLE seq_item_code (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  venue_id BIGINT UNSIGNED NOT NULL, year SMALLINT NOT NULL, month TINYINT NOT NULL,
  cur_prefix VARCHAR(3) NOT NULL DEFAULT 'A', cur_seq SMALLINT NOT NULL DEFAULT 0 COMMENT '已用最大流水',

```

### 5.3 其余 15 张表（要点）

| 表 | 关键设计 |
|----|---------|
| sys_user | username 唯一；password_hash(BCrypt12)；role(1管理员/2可编辑/3仅查看)；locale 默认 ja-JP；failed_attempts/locked_until；must_change_pwd；用户只停用不删 |
| auction_venue | code CHAR(2) `[A-Z]{2}` 唯一；有商品引用只停用不物理删 |
| year_code | year↔code(CHAR1) 双唯一；种子：2016=A、不跳 I/O（2026=K/2027=L 吻合需求示例；2035=T、2041=Z）；Z 用尽后续规则待甲方 |
| price_band | code 字母唯一；lower_bound 含/upper_bound 不含（NULL=末档开区间）；CHECK lower<upper；区间重叠由服务层 FOR UPDATE 校验；只停用不删，不回溯历史 |

## 七、关键技术方案

### 7.0 写操作幂等契约（唯一定义节）

所有写操作携带客户端生成的幂等键，服务端**先按键查结果：命中→返回 200+原结果（UPSERT 语义，绝不 409——否则网络切换中响应丢失后的机器重放会让前端退避打到封顶死循环）；未命中→执行+落键**：
- **clientReqId**（业务操作：POST /items、PUT /items、/inventory/* 全部动作）：落 stock_ledger.client_req_id，命中先 SELECT 读回原结果语义（重放返回首次结果、不产生第二条流水）——网络超时重试双执行是账实错乱的直接来源；防的不只是数据还有人：重放若对用户表现为 500，业务员会照草稿人肉重录提交新键=重复件。集成测试断言「同键连发两次 /inventory/sell→第二次返回首次结果+ledger 仅 1 行」
- **clientUuid**（图片上传）：落 item_image.client_uuid，重复上传返回 200+已有 image 记录，队列据此出清
- **批次 sha**（用户主动重复提交，语义不同应提示而非静默合并）：CSV=file_sha256 同文件 409；Excel 导入批次 sha 同理 409

### 7.1 管理号引擎（并发防重核心）

**格式**：`{会场2}{年代号1}{月1-2不补零}-{流水前缀}{1-99}{价格码1}`，正则 `^([A-Z]{2})([A-Z])([1-9]|1[0-2])-([A-Z]+)([0-9]{1,2})([A-Z])$`；前缀 base-26 递进 A→Z→AA（Z99 后接 AA1，覆盖单桶 2574+ 需求未定义场景，`-` 保证无歧义）。A1 矛盾由 include_price_code 解（application.yml 属性，M2 确认后固化）。桶=venue+落札年+月，**来源是落札日期而非系统时间**——补录上月落札进上月桶继续递增。

**生成算法**（ItemCodeGenerator；重试必须在事务边界之外——死锁后 InnoDB 已自动回滚整个事务、DuplicateKey 后 Spring 已标 rollback-only，事务内 catch 重试必然 UnexpectedRollbackException）：
1. 外层 saveWithRetry()（无 @Transactional）循环 ≤3 次，每次经独立事务 bean ItemCodeTxService（规避 AOP 自调用失效）调用 @Transactional 的 allocateAndInsert()
2. 事务内：入口先按 clientReqId 查 CREATE 流水，命中=网络超时重放→直接返回原 item 200 不再取号 → 锁外前置校验（年代号存在/档位匹配，400 不进锁）→ SELECT ... FOR UPDATE 锁桶行（桶不存在 INSERT IGNORE 后重锁）→ cur_seq<99 则 +1 否则前缀进位归 1 → 同事务 UPDATE 计数器 → INSERT item（uk_item_code 兜底）+ CREATE 流水
3. DuplicateKey/死锁/建桶竞争 → 外层重新进入全新事务（统一单层重试计数，无嵌套）→ 仍败 500+告警
4. **跳号语义文档化**：重试取新号不复用旧号、Excel 旧号导入推进计数器——唯一性是硬约束、连续性不是；跳号事件写 operation_log 供巡检

正确性：同桶并发在步骤 2 串行化（行锁持至提交，锁内纯写毫秒级）；不同桶零阻塞；计数器只进不退，作废/软删的号继续占位（行还在、唯一键仍生效）=天然不复用。已否决：MAX(item_code) 取号（不原子）、Redis INCR（破坏单 MySQL 拓扑）。

**预览语义**（前端文案必须体现）：preview 接口无锁只读，两人可能同见 HTK9-A24X；先保存者得 A24，后者落库得 A25——预览号≠保留号，最终以保存响应为准。前端两级预览：档位字母本地缓存即时算；流水号用「上次保存号+1」本地推算，失焦时调 preview 校正。

**锁定规则（snapshot 单模式）**——需求 3.1「生成后锁定」与十三「改字段不改号」的矛盾，以十三（需求文档自己的异常裁决节，是对 3.1 含糊单元格的权威解释）为准：
- 会场/落札日期/进货价可自由修改，**管理号恒不变**——号内各段本就是生成时快照列（venue_code/year_code/buy_month/price_band_code），允许与现值分歧，详情页显示「号内快照≠现值」提示徽标；作废重录保留为纠错路径（错价场景推荐走此路径，号内字母恢复一致）
- 手续费/运费/税/货架/备注/组号/图片自由改；改价后档位快照重推导（仅供内部看；include_price_code=false 时不进号）
- **仓库边界（防绕过台账）**：在途商品可 PUT 改「预计仓库」；在库商品改仓必须走 /inventory/transfer（TRANSFER 流水），PUT 直改在库仓库 → 409 WAREHOUSE_TRANSFER_REQUIRED（对账不变量测试覆盖此用例）

**作废重录全路径**：入口=录入成功页「重录上一件」+ 商品详情页「作废」（E 可用，不限仅上一件）；作废后预填表单携带原商品全部字段与已上传图片（新号生成、图片绑定新商品，不要求重拍）；扫已作废号 → 提示「该号已作废（原因/时间/操作人，重录后的新号——re_entry_of 互链），请核对实物」；作废确认弹层附「请撕除/划掉该件旧标签」；新旧件 remark 自动互写「重录自 XX／被重录为 XX」。

### 7.2 双状态机与库存流水

| 动作 | 库存状态 | 销售状态 | ledger 类型 | qty |
|------|---------|---------|------------|-----|
| 录入 | →在途 | →未上架 | CREATE | 0 |
| 到仓扫码 | 在途→在库 | 不变 | ARRIVAL | +1 |
| 卖出（须在库） | 在库→已出库 | →成交 | SELL（ref_id→yahoo_listing） | −1 |
| 报废（须在库） | 在库→已出库 | 任意销售态→取消 | SCRAP（reason 必填） | −1 |
| 调拨（须在库） | 不变，仓 A→B | 不变 | TRANSFER | 0 |
| 退货·顾客退回 | 已出库→在库 | 成交→取消 | RETURN | +1 |
| 退货·退回拍卖场 | 在途/在库→已出库 | 在售→取消 | RETURN（在途退回 from_wh=NULL，不影响仓账） | −1 |
| 上架/成交/取消标记（CSV 或手动） | 不变（实物未动） | 单调状态机只前进：未上架→在售、在售→成交/取消、取消→在售（重新出品）允许；禁止回退（陈旧 CSV 不会把成交刷回在售）；手动上架标记（E，/inventory/mark-listed）供雅虎手工出品后即时登记 | LIST_UP/SOLD_MARK/CANCEL_MARK | 0 |
| 盘点调整 盘亏/盘盈/仓错 | 对应修正 | 不变 | STOCKTAKE_ADJUST | ±1/0 |
| 作废 | 冻结（禁一切变动） | 冻结 | VOID（在库记 −1、在途/已出库记 0） | −1/0 |
| 回收站删除（A） | 在库→冻结（可恢复） | 冻结 | RECYCLE_DELETE（在库记 −1） | −1/0 |
| 回收站恢复（A） | 冻结→原库存态 | 原销售态 | RECYCLE_RESTORE（恢复为在库记 +1） | +1/0 |
| 手工修正（A，须 reason） | 任意→任意 | 任意→任意 | ADJUST | 按边推导 |

**销售状态（数据事实）与库存状态（实物事实）解耦**：CSV 标记成交后实物仍须扫码卖出才出库，二者差集=/yahoo/reconcile 对账视图（**三活视图**：已成交未出库 / 流拍未重新出品 / 已出库但雅虎仍在售=「要撤架清单」——防一件货卖两次，行内标注最后同步时间、7 天内同步过的降灰提示[CSV 滞后期假阳性]；「CSV 有而系统无」并入每批导入报告 unmatched 计数[含 raw_item_code 原文码]）。「已成交未出库」同时以「出荷待ち（发货待办）」业务入口双端呈现（雅虎成交→打款→打包发货有数天时滞，是仓库每天的拣货队列而非异常——对账视角保留成交超 N 天未出库的滞留标红）。

**sold_price 双源优先级**：CSV 成交价 > 手填（手填仅无 CSV 成交记录时生效），冲突在 reconcile 视图提示人工裁决。每次变动=单本地事务：clientReqId 先 SELECT 读回原结果 → 乐观锁读 item（冲突重读 1 次→409）→ 状态机校验边（非法 409）→ 更新 item → INSERT ledger → 同事务审计 → 提交后 SSE 推送。InventoryStateMachine=机器可读五元组边表 `(action, stock_from, stock_to, sale_from, sale_to)`，逐 action 全枚举（含 CSV 三标记/盘点三确认/回收站删除恢复/作废/报废×各销售态），单测由边表参数化生成全合法边+全非法边。**MyBatis-Plus 生成列陷阱**：total_cost/profit 实体标 `@TableField(insertStrategy=NEVER, updateStrategy=NEVER)` + 读改写集成测试（防 MySQL 3105）。**选型验证**：Spring Statemachine 已进 spring-attic 存档（勿引入）——手搓五元组边表即正确路线（KISS）。

**作业流程约定（写入操作手册）**：调拨扫码在到货卸货端执行（否则卡车在途 1-2 天内系统已换仓，撞盘点产生需人工裁决的差异——差异行已带变动流水标注辅助裁决）；标签贴商品本体/吊牌不贴外箱（退货回来标签随外箱丢失，兜底=雅虎订单商品コード手输）；「录一件贴一件」=「录一件抄一件（油性笔）+回社贴一件（标签）」。

### 7.3 扫码盘点（差异人工确认才调账）

发起（选仓库）→ 手机逐件扫码（重复扫 repeated=true；扫到他仓货即时黄条警示照记）→ close 冻结（期望集合=close 时刻该仓在库未删未废；盘点期间的自然变动落入差异由人工裁决，语义文档化）→ 生成差异表（盘亏=期望有未扫到 / 盘盈=扫到但系统非在库 / 仓错=仓库不符 / 冻结品=扫到已作废或回收站商品——单独分类，提示走恢复或线下处理，禁止 CONFIRM 调整冻结品；差异行标注「盘点期间发生过变动流水」辅助裁决）→ 逐条 CONFIRM（应用变更+STOCKTAKE_ADJUST 流水，ref 指向盘点单）或 IGNORE（留痕）→ 全处理完单据已确认。谁发起/谁扫/谁确认全程双留痕。

### 7.4 雅虎 CSV 导入管线（异步+双幂等）

上传（≤50MB+行数上限 20 万）→ 存原始文件(sha256 命名) → 建 batch（同步线程内捕获 userId/userName 显式传参——异步线程无 SecurityContext）→ 立即返回 batchId → 专用单线程有界执行器（core=1/max=1；串行化顺带保证批次按提交顺序处理）后台：**编码检测**（BOM → juniversalchardet → SHIFT_JIS/Windows-31J 一律按 MS932 严格解码验证，失败走候选链 UTF-8→MS932→EUC-JP，全败批次失败）→ **清洗**（commons-csv 支持引号内逗号换行；全角数字字母空格→半角；数字字段去 ￥/¥/円/千分位；管理号 trim+大写+正则；自由文本仅 trim 保护原样；日期双格式）→ **匹配**（管理号走 uk_item_code 精确等值）→ **合并**（一行=一次出品，UNIQUE(yahoo_auction_id) UPSERT；listing 状态走单调状态机只前进，价格 recency=GREATEST(closed_at, listed_at)+批次序号 tie-break——重传陈旧旧导出不会把成交刷回在售/旧价覆盖新价；出品/取消次数=COUNT 派生，天然幂等永不重复累计）→ **回写**（每商品 REQUIRES_NEW 独立事务，坏行不连坐；绝不改 stock_status）→ SSE yahoo.import_done → 报告（匹配/未匹配/错误行）。批次幂等：UNIQUE(file_sha256) 同文件 409；僵尸自愈：app 启动把 processing>30min 的批次标记 failed 并释放 sha 占位允许重传。列映射从 application.yml 读 JSON（雅虎格式变更本需发版验证，JSON 编辑框是给非技术甲方的陷阱；样张到位前改配置重启即适配）。

### 7.5 图片管线（弱网优先，先存后传）

拍摄/相册（capture=environment；photo_date：拍照=今天；相册选图=EXIF DateTimeOriginal 优先、无 EXIF 手动选填，不默认今天）→ 压缩（≤0.3MB/1920px/jpeg，Web Worker）→ arrayBuffer() 即刻入 Dexie 队列（崩溃/刷新不丢）→ **文字先保存**（POST /items 拿到 itemId 后队列绑定才开始传；文字保存失败=孤儿态 pending_bind：独立「未提交照片」区，支持「重试保存」（草稿预填重提）、「全部重试」与「放弃」）→ 并发 2-3 路上传（单 item 内保序，300 张总时长降约 60%；上传中进度条+pagehide 提示「N 张未传完」）；幂等契约：重复 clientUuid 返回 200+已有 image 记录（见 7.0）；队列状态机：启动扫描将遗留 uploading 强制复位 pending（否则僵尸队头阻塞整个队列）→ 退避 1s→5s→30s→5min 封顶+jitter、attempts 无上限、online 事件立即重置 → 触发矩阵：页面存活循环 + visibilitychange→visible（iOS 打开即补传）+ 安卓一次性 Background Sync（联网数分钟内触发，主路径；不用 workbox-background-sync——请求体全量序列化进 IndexedDB 大图场景不稳）+ 启动全量扫描。

**诚实结论：iOS 无后台补传（系统限制，Web Push 不能拉起业务 JS）——四件套兜底**：打开即补传+页内角标 N+pagehide「N 张未传完」警示+主屏安装引导。**主屏安装=数据安全前提而非可选 UX**：未加主屏的 Safari 标签页 ITP 7 天无交互即清空 IndexedDB（WebKit 官方行为，主屏豁免）——首次登录检测非 standalone 出日文安装引导，队列非空且未安装则页头持续警示条+navigator.storage.persist() 加保险。压缩后单图≤400KB 不做分片续传（对 300KB 过度设计）——断点语义由持久化队列+幂等键达成。

后端：magic bytes 白名单（JPEG/PNG）+≤5MB+解码前读头校验像素上限 8000×8000（防像素炸弹 OOM）+UUID 路径 → 服务端统一重编码原图（重编码即剥离 EXIF/GPS、归一格式——防绕过客户端直传 API 泄露仓库/拍卖场精确坐标）→ 256px/0.7 缩略图，列表只传缩略图(~25KB)。上传治理：磁盘水位检查（超阈值 507 DISK_FULL+sys_alert 落库；上传队列遇 507 停止重试并提示联系管理员）+孤儿文件定期清理（并入每日自检 job）。图片 nginx 只读挂载直出（expires 30d immutable+X-Robots-Tag: noindex+robots.txt）。**边界声明（文档+界面文案）**：完全离线无法录入（管理号需服务端行锁生成，架构决定而非缺陷）——弱网提示「信号弱请稍后重试，照片与草稿不会丢」。

### 7.6 实时同步（SSE）

单向通知场景 → SSE：SseHub（userId→emitters，emitter 同时登记 sessionId；sessionDestroyed（登出/被踢/12h 过期）→立即关闭该会话全部 SSE 连接；per-emitter 串行化 send，SseEmitter 非线程安全）+ 20s 心跳注释防代理超时；事件信封 `{seq,type,entity,operatorId,at}`，类型覆盖 item/库存/图片/盘点/导入/设置/字典变更 + session_kicked（被踢端即时提示）。前端 useSse()：Pinia 单例（路由切换不重建、登出必 close）；EventSource 同源自动带 Cookie、error 回调探测 /auth/me 401→es.close() 跳登录（原生重连对 401 无限风暴）、visibilitychange→visible 主动 close 旧连接再重建（iOS 挂起掐线后原生重连不可靠）、断线>5s 或切回前台全量刷新；处理策略=粗粒度失效+500ms 防抖重取（不传增量补丁，5 万行重取成本低且无补丁 bug）。nginx /api/sync/ 段五件套：proxy_buffering off; gzip off; proxy_http_version 1.1; proxy_set_header Connection ""; proxy_read_timeout 1h + 应用侧 X-Accel-Buffering: no 双保险。spring.mvc.async.request-timeout=12h 显式配置；per-emitter send 加 ~5s 超时，超时即 completeWithError 断连；HikariCP maximumPoolSize=16（10 并发录入压测下零余量）。SSE 不占 JDBC 连接不占 servlet 线程（SseEmitter=startAsync，长连接归 NIO connector）。**30s 轮询为已评估的简化备选**：唯一损失=亚秒级跨端新鲜度；需求一显式承诺「多人同时操作实时一致」，砍除需甲方对「实时」口径确认；切换是纯增量。

### 7.7 二维码与标签打印

二维码生成唯一实现在前端 qrcode 库：录入成功页即时展示（离线可用）、打印页、单件重打共用——「码内容=管理号」单一实现防口径分叉。万一甲方特定打印机上浏览器打印仍对不齐，PDF 服务端兜底是半天级纯增量，届时再加。QR 规格（防「码印出来扫不动」）：ECC=M、quiet zone≥4 模块、模块尺寸≥0.5mm、码边长≥14mm（管理号 8 字符=QR Version 1 容量足够）、目标 300DPI；标签必含人眼可读管理号文字（会场/日期段分行）；打印页顶固定引导条「缩放 100%／边距无／取消页眉页脚」（用户打印对话框缩放是模块尺寸偏离主因，非 CSS）。

## 八、安全设计

- **会话**：Spring Security 6；JSESSIONID HttpOnly+Secure+SameSite=Strict；12h 滑动；同账号多端上限 8（iOS PWA 与 Safari cookie 相互独立，5 易误踢；注册 HttpSessionEventPublisher）；登录成功 changeSessionId 防固定；未认证 401 JSON 不重定向；部署铁律：前后端必须同源部署，否则 SameSite=Strict 失效（写入部署文档）；SSE 连接随会话失效立即关闭
- **CSRF**：SameSite=Strict + OriginCheckFilter（非 GET 且 Origin≠配置域 → 403）双保险，免 token
- **锁定防爆破**：（账号+IP）维度 5 次错→锁 15 分钟（满足需求字面；纯账号维度可被武器化为全员 DoS），跨 IP 失败走渐进延迟+审计告警；锁定中 423+剩余分钟；未知用户名对 dummy hash 跑 BCrypt 抹平时序（防用户枚举）；计数原子 UPDATE；管理员手动解锁端点；全部尝试（成败）写日志含 IP
- **密码**：BCrypt strength 12（DelegatingPasswordEncoder）+ 最小 10 字符 + Top1000 弱口令拒绝；管理员重置→强制下次改密
- **RBAC**：@EnableMethodSecurity 注解化 + 服务层敏感操作二次校验；权限矩阵=第六节清单（每端点唯一角色集合，机器可展开；仅查看可见成本/利润=需求字面默认），测试全展开
- **审计**：AuditRecorder 业务事务内同步写（与业务原子，绝不丢审计）；detail 前后值 diff；MetaObjectHandler 自动填 created_by/updated_by
- **上传**：magic bytes 白名单（JPEG/PNG）+≤5MB+读头像素上限 8000×8000+UUID 路径（用户文件名不参与）+服务端统一重编码剥 EXIF/GPS；Excel 校验 zip magic+行数上限；导出公式注入消毒（=+-@ 前缀单元格强制文本格式）
- **DB 账号分离**（显式最小 GRANT，而非 ALL 再 REVOKE 减法）：kcgl 业务账号=业务表 SELECT,INSERT,UPDATE,DELETE；stock_ledger/operation_log 仅 SELECT,INSERT；不给任何业务账号 DROP/ALTER/TRUNCATE（root 与 kcgl_migrate 除外，migrate 走独立 init 容器跑完即退）；集成测试逐项断言；部署包内置 verify-grants.sh 自检
- **注入/XSS**：MyBatis 全 #{} 参数化（列表排序参数列名白名单，唯一 ${} 注入面）；Vue 默认转义禁 v-html；CSP `default-src 'self'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'` + Referrer-Policy；无 CORS（同源 SPA）
- **HTTPS**：TLS1.2/1.3 + HSTS + 80→443 跳转；安全头 nosniff/DENY
- **生产收敛**：prod profile 关闭 springdoc；actuator 仅暴露 health 且 details=never
- **备份**（唯一定义节）：mysqldump 每日 03:30 `--single-transaction --set-gtid-purged=OFF` 管道 zstd 压缩（SQL 文本 5-8 倍压缩比）+ 图片 rsync --link-dest 硬链快照（日 7+周 4；运维禁令：不得整批重生成缩略图/重编码——换 inode 会使硬链快照单次膨胀一份全量，写入 runbook）；cron 统一 CRON_TZ=Asia/Tokyo；dump 目录 700/文件 600、凭据 root-only env 600 不入 git；backup.sh 开头磁盘水位>80% 拒跑并告警；恢复演练=restore.sh --verify（恢复到临时库跑对账不变量后丢弃；按需触发：发版演练/backup.sh 改动后/大版本升级前）；binlog binlog_expire_logs_seconds=604800；容量：45GB 存量+首个快照全量再 45GB → 磁盘预留 ≥150GB + 应用内每日磁盘水位检查 → sys_alert

### 9.3 可观测性与远程支持（生产=我方无服务器权限+非技术甲方，远程排障的地基）

**核心组合：errorId 贯穿的日志 + 一键诊断导出；M1 落地，不留到末期**：
- **日志规范**：结构化单行 JSON（Boot 3.4+ 原生 logging.structured.format=ecs）；生产 root=INFO；入口 Filter 生成 8 位 traceId 入 MDC（userId/item_code/client_req_id/batchId 按需补充）；自定义 ThreadPoolTaskExecutor 显式 setTaskDecorator 传播 MDC；内存环形缓冲保留最近 500 条 ERROR/WARN 供诊断导出
- **errorId 闭环**：GlobalExceptionHandler 异常→ERROR 日志（traceId+端点+clientReqId+业务键）→响应体 {code,message,data,errorId}→前端 toast「エラー発生 ID: xxxx／管理者に連絡してください」——用户报 ID，我方拿 ID 对日志
- **前端错误上报**：window.onerror+unhandledrejection+Vue errorHandler+上传队列 attempts 超阈值 → POST /client-errors（登录会话内+限流+字段白名单+stack 截断+每用户日上限）→client_error 表+管理页+诊断导出；登录心跳顺带上报队列统计
- **诊断信息一键导出**（管理后台）：版本+构建号/Flyway 当前版本/uptime/health 自检/磁盘可用/最近备份标记/sys_alert 近 30 条/环形缓冲错误（含 traceId）/client_errors 统计/SSE 连接数/HikariCP 池峰值/CSV 批次近况/doctor 输出——白名单字段导出，甲方动作=点按钮发文件
- **告警通道**：统一落 sys_alert（管理后台红点+登录页横幅+SSE 推送）+ backup.sh 写状态标记由 app 读取入告警；外部拨测兜底：我方测试服务器上加拨测容器监控生产公开 URL（HTTPS 可达+登录页 200+证书剩余天数），故障通知我方
- **システム状況页**（管理员）：SSE 连接数/CSV 批次时长与失败数/上传成功失败计数/号引擎重试与跳号计数/HikariCP 池/JVM 堆/磁盘水位/client_errors 近 7 日；Prometheus 端点仅测试环境内网开
- **系统级故障用户文案矩阵**：DISK_FULL(507)/DB_UNAVAILABLE/SERVICE_UNAVAILABLE → errors.json 三语文案+errorId 同屏；上传队列遇 507 停止重试
- **日志纪律**：允许 item_code/userId/clientReqId/venue_code/traceId；禁止备注全文/完整请求体/原始文件名
- **明确不要（过度设计已否决）**：ELK/Loki（日日志量 KB 级）；Prometheus+Grafana+Alertmanager 栈；Sentry 自托管；OpenTelemetry 全链路追踪（单体 MDC 短 ID 足够）；on-call 体系（10 用户次日响应合理 SLA）
